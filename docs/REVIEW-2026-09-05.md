# Repository review — 2026-09-05

Reviewed from `ae808ab` on `main`, alongside the CS:S reference repository.
This pass covered gameplay state and lifecycle handling, statistics,
website authentication and storage, RCON transport, deployment configuration,
release tooling, and the existing regression tests. The
[visual overview](OVERVIEW.md) explains how the components fit together.

## Fixed findings

| Area | Failure or unnecessary work | Change |
| --- | --- | --- |
| AFK detection | Saved native position/angle wrappers could reflect later entity movement instead of the earlier sample. Active players could appear idle. | Capture numeric values; poll once per second and reuse one player enumeration. The existing two-of-three inactivity rule is preserved. |
| Goal attribution | Repeated dribble touches replaced the passer with the eventual scorer; a reused connection slot could inherit touch credit. | Preserve the preceding distinct toucher; clear departed slots and reset touch history when the ball is reset. |
| Match statistics | Counters from an aborted match could carry into the next match. Player record lookup scanned all stored entries on every update. | Reset match counters on a new match; index player entries by SteamID and count teams in one enumeration. |
| Lifecycle cleanup | Map changes or plugin unload could leave unsaved statistics or temporary password/respawn settings behind. | Save statistics and restore temporary AFK/password and goal-respawn settings during cleanup. |
| SQLite | Using a connection as a transaction context did not close it. Container storage defaulted to an ephemeral directory despite a named volume. | Close connections after commit/rollback; set Compose storage to writable `/data` and document migration of existing databases. |
| Request handling | Malformed session expiry values, non-ASCII tokens, redirects containing control characters, or non-integer half lengths could cause errors or unsafe redirects. | Validate types, encoding, size, expiry and redirect characters before use. |
| RCON transport | A single read could truncate a command response and desynchronize later commands; concurrent roster imports could interleave. | Assemble bounded response chunks using protocol fences and serialize command batches per game. Reject malformed framing. |
| RCON configuration | Quoted passwords containing `//` were truncated; CS:S had no environment-password option for containers. | Parse quoted values correctly and accept `CSS_RCON_PASSWORD`. |
| Container wiring | Every service received all secrets; helper addressing relied on an unspecified Docker gateway. | Pass only needed environment values to each service and explicitly configure the private subnet/gateway. |
| Regression coverage | Thirteen baseline failures asserted older menu, appearance, sprint HUD, camera or cap behavior. | Align assertions with the current documented source behavior and add executable Python and managed regression tests. |

Existing deliberate gameplay choices remain: public match/map controls,
conditional in-game captain picks, team tint, and the removed sprint HUD
and glow. No physics constants or native signatures were retuned without
server measurements.

The managed runner executes storage/cleanup methods from the real assembly
without initializing a native game host. The Python tests exercise real
SQLite files and deterministic socket fixtures, including fragmented
headers and multi-packet command batches. These checks do not simulate
a full game server.

CI now includes the Python and managed checks plus release packaging and
a Linux installer smoke test. The install fixture now provides both
required runtime directories. The new CI job has not been observed on
GitHub during this local review. PowerShell packaging and the Linux
installer were not executed locally.

## Operational follow-up

Test on a Linux staging server before deploying: ball spin and native
bridge loading, goal/assist/save credit through dribbles and reconnects,
AFK movement challenges, map changes, aborted/new matches, and
simultaneous website requests. Native bridge compatibility depends on
the installed game build and signatures.

Docker is unavailable on the review machine, so container startup,
Steam OpenID and live RCON were not integration-tested. Existing website
operators must follow the database migration instructions in
[kickoff/README.md](../kickoff/README.md) before recreating an old container
that stored data under `/tmp`.

No live server configuration, game binaries, deployment or GitHub release
was changed by this review. The source fixes do not update already
published release archives.
