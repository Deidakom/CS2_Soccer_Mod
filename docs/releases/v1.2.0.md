# Ball handling 1.2.0

The map's single visible Workshop ball and existing power/size settings remain
in use. The default `improved` profile changes contact handling; `legacy`
restores the previous gameplay paths without a binary replacement.

## Profiles and controls

Run these in the server console or RCON (ball admins can also use them in game):

| Command | Result |
| --- | --- |
| `css_sm2ball_profile improved` | 3D contacts, deterministic simultaneous dribbles, shared training wall/ground rules, contact spin; no random wall pop. Default for this deployment. |
| `css_sm2ball_profile legacy` | Immediate behavior rollback to the previous contact, spin, wall-pop and training paths. |
| `css_sm2ball_profile creative` | Improved handling plus optional aim-offset airborne curve and deliberately armed first touch. |
| `css_sm2ball_runtime` | Actual Workshop model, profile, schema angular value and rotation-derived angular sample. |

The selection is atomic and persistent in `soccermod_ball_handling.json`.
Existing `soccermod_settings.json` tuning is not migrated or overwritten by a
profile switch. Both mouse buttons and sprint retain their controls.

In creative mode, bind an unused key to `css_ball_trap`. One press arms a
0.35-second cushion window with a one-second recovery. The next accepted
incoming contact retains 20% of relative ball speed; the ball is never attached
to the player. This is deliberately a skill input, not automatic possession.
Aim to either side of the centre for a modest curve; centre strikes have none.
Airborne curve decays, lasts at most 1.25 seconds, preserves speed and vertical
velocity, and stops at a wall/contact. It is optional arcade aerodynamics,
not a claim that CS:S models this force.

Training admins outside an active match can use:

- `css_ball_target`: place a 48-unit practice target at the crosshair.
- `css_ball_target wall`: require a wall rebound before reaching the target.
- `css_ball_target off`: remove the drill.
- `css_ball_replay`: show the last personal-ball shot as a non-colliding path.

Replay samples the owner's personal ball for five seconds. It displays at most
24 line segments per request, lasts eight seconds and has a global 128-line
cap. Targets and paths are visible training overlays, not private spectator
features. They clear on map changes, unload, profile switches and match start.
Training balls use the same wall detector, correction ownership and local
surface traces as the match ball, while scoring remains match-only.

## Contact fixes

Wall separation callbacks belong to one ball lifetime and contact generation.
A newer kick, push, impact or reset cancels them. They correct only missing
wall-normal speed, preserving current gravity/tangent velocity; a changed
surface or reverse motion ends the correction.

Player impacts sweep a sphere against each live pawn's actual collision-height
capsule in relative motion. Vertical drops and crossings beyond the player's
centre are accepted at entry. The earliest contact wins; tied entries use slot
order. Knockback callbacks retain pawn identity and contact sequence, so a new
pawn or newer impact cannot inherit an older correction. Damage stays disabled.
Simultaneous body pushes are reduced in stable order and averaged, preventing
last-writer wins and stacked player-count boosts.

## Spin and measurement limits

Off-centre strike torque uses `contact offset × kick delta`. Angular momentum
is estimated from successive real ball orientations because Rubikon props can
report zero through the entity's `AngVelocity` schema. The local-space additive
impulse is bounded against that sample (experimental 6000 degrees/second cap).
Unavailable/stale samples skip spin injection instead of blindly stacking it.
Wall rebounds preserve spin rather than claiming an additive impulse sets an
absolute target. The legacy profile retains the previous topspin behavior.

This is sampled angular readback, **not** a new native mass/inertia API or a
synchronous acknowledgement that Rubikon accepted an impulse. Fast rotation can
alias between ticks. Exact native readback and CS:S calibration remain follow-up
work; no unverified memory offsets were added to the server.

Reference trials now identify the actual active model. A trial with observed
spin first requests its cancellation and asks for a retry after two awake ticks;
it will not launch until rotation is observed below one degree/second. The
native request itself is not treated as success. `flightside` adds a Z-axis
sidespin trial alongside the existing Y-axis `flightspin`. Angular samples are
logged separately. Roll/drop/flight captures are still affected by the selected
gameplay profile; use matching profile/config captures when comparing results.

The CS:S repository now ships the same 1.3.0 probe as this repository, including
native player-impact trials. No reference ball gameplay was changed there.

## Deployment and full rollback

`deploy/testserver/install-ball-handling.sh DLL SHA256` validates the artifact,
stops `cs2-soccermod-test.service`, snapshots the whole existing plugin folder
under `/home/gameserver/cs2-soccermod-backups/ball-handling-*`, then installs the
new DLL and selects `improved`. Installation failures attempt automatic recovery.
Check `css_plugins list`, `css_sm2ball_runtime` and server logs after startup;
a systemd active state alone does not prove the managed plugin loaded.

Each backup has `rollback.sh`. Running it as root restores the exact old DLL
and ball settings, then restarts the service. It preserves the latest ranks,
bans, admins and match data. The complete snapshot is retained separately for
manual recovery. The deployment report records the concrete backup path.

Validated locally: 25 managed scenarios (14 production ball-math cases),
100 Node tests, 14 Python tests including failed-deploy recovery and rollback
that preserves new ranks, Release build with zero warnings, and all eight
CS:S plugins compiled. Live ball feel, human multi-player contacts and client
training-overlay appearance require in-game A/B testing. This release does not
claim a measured 5–10% match to CS:S trajectories.

Live deployment findings, including the unsuccessful native sidespin request,
are recorded in [the deployment report](../deployments/2026-09-05-ball-handling.md).
