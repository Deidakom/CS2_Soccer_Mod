# HUD, menu and halftime changes — 2026-09-05

Four in-game reports, all fixed in one build.

## 1. `!menu` fits on one page

The HTML panel held 3 rows, so the 7-entry main menu spanned 3 pages and
needed two presses of `9 Next`. The CS2 centre-HTML panel is a fixed client
element that clips past a line budget — it cannot be made taller, only
denser. Rows now default to **7** (the ceiling: keys 8/9/0 are reserved for
Back/Next/Close) in the smaller `fontSize-sm`. A single-page menu also drops
the `1/1` counter and folds `0 Close` onto the heading line, buying two more
lines before the clip edge.

Because only the client can see where it clips, both knobs are live-tunable
and persisted (`soccermod_settings.json`):

Two header layouts:

- **Single-page menu**: navigation shares the title's line —
  `8 Back | Title | 0 Close` — so the seven-entry main menu stays on one page.
- **Paged menu**: the four-item line (`8 Back | Title 1/3 | 9 Next | 0 Close`)
  kept wrapping on the client whatever the font, with `0 Close` orphaned on a
  second line. The title now owns line one and the paging keys sit on their own
  line beneath it (`8 Back | 1/3 | 9 Next | 0 Close`); a paged page gives two
  rows back (5 instead of 7) and the last items move to the next page — the
  user explicitly accepted that trade.

| Command | Meaning |
|---|---|
| `css_sm2menu_rows <1-7>` | options per HTML page |
| `css_sm2menu_font <s\|sm\|m\|l>` | row font size |
| `css_sm2menu_navfont <s\|sm\|m\|l>` | font for `8 Back` / `p/N` / `9 Next` / `0 Close` |
| `css_sm2menu_pagedrow <0-3>` | rows a paged menu gives back for its two-line header (default 2) |

If the panel still clips: `css_sm2menu_font s`, then `css_sm2menu_rows 6`. If
paged pages have room to spare, `css_sm2menu_pagedrow 1` gives them six rows.
No redeploy needed for any of it.

## 1b. Body push works on the first touch after a round start

Every round start `DisableMotion`s the ball (`ForceBallFullStop`) so it cannot
creep before anyone touches it, and only `UnfreezeBallForPlay` hands it back to
physics. The kick reaches that unfreeze unconditionally, but the body push only
reached it *after* its approach-speed gate — and a `DisableMotion`ed prop is a
static wall, so the engine clipped the player's velocity to zero on contact and
the gate never passed. Result: "the ball blocks for a second when I walk into
it"; the journal showed 25 round-start freezes ending in a kick and one in a
push. The first eligible body **contact** (same eligibility, kickoff, height and
distance gates as the push) now unfreezes the ball on that tick
(`ball_unfrozen reason=body_contact`), and the normal kickstart push follows
from the next tick — the same feel as touching a settled ball. Nothing within
contact distance still means nothing unfreezes, so creep protection is intact.

**Why the panel can't simply be made bigger:** `PrintToCenterHtml` writes
into a fixed Panorama element owned by the client — the server sends only an
HTML string and has no width/height/scroll control. And even with unlimited
height, options are selected with keys 1-9 while 8/9/0 are Back/Next/Close,
so ~7 per page is the input ceiling, not a layout one. A genuinely larger,
scrollable menu needs the Classic/Panorama renderer
(`src/workshop-addon/soccermod_classic_ui/`), which is written but whose
readiness handshake has never fired on the live server.

## 2. Sprint meter is standalone

`SprintBarView.Html` used to prepend the match score/time above the meter.
That put the same text on the **HTML** centre channel that the match banner
writes to the **plain** centre channel. They are independent client channels,
and a plain write lingers for seconds and cannot be revoked — so whenever the
bar happened to be hidden on a 1 Hz banner tick and then reappeared, both
panels were on screen at once, with different timestamps (the lower one
stale). The meter now renders the bar and nothing else.

## 3. Match clock on the native HUD round timer

The match clock is written into CS2's own top-centre round timer instead of a
centre-screen banner. `SyncNativeRoundClock` (Match.cs) writes
`CCSGameRules.RoundTime` + `RoundStartTime` at 1 Hz and on every phase change,
networked through `CCSGameRulesProxy`/`m_pGameRules`. The client renders
`RoundTime - (curtime - RoundStartTime)` and counts down by itself between
writes; `RoundStartTime` is shifted by the fractional part so the displayed
value lands exactly on the remaining time and the 1 Hz rewrite never jumps.

Behaviour: counts down when live, freezes while paused / waiting for the ball
at kickoff / during a goal pause, shows the break countdown at halftime, and
is handed back to CS2 (`mp_roundtime`) at full time or on `!match stop`.
`mp_restartgame` at each kickoff resets the clock, so `MatchOnRoundStart`
re-stamps it on the next frame, like the team scoreboard already does.

The period label has no room on the timer, so the hostname now carries it
(`LIVE 1/2`, `KICKOFF 2/2`); the kickoff chat lines already did.

| Command | Meaning |
|---|---|
| `css_sm2match_clock native` | match time on the CS2 HUD round timer (default) |
| `css_sm2match_clock banner` | legacy centre-text banner |
| `css_sm2match_clock` | diagnostic: mode, phase, remaining, RoundTime, RoundStartTime, curtime, hudSeconds |

`hudSeconds` in that diagnostic is what the client actually renders — it must
track `remaining` within a tick. Also in `!menu → Admin → Match → Match Info`.

**Known risk:** `MenuApplyHtmlFlickerSuppression` holds
`CCSGameRules.m_bGameRestart = true` while an HTML menu or HTML sprint bar is
visible (i.e. during most sprints). If the client hides or freezes the round
timer under that flag, the timer will misbehave exactly while sprinting.
Fallback in order: `css_sm2match_clock banner` (instant, no redeploy), or drop
the `_sprintBars` term from `wantActive` in Menu.cs so suppression only
applies while a menu is open.

## 4. Halftime break 60s → 3s

`DefaultBreakLengthSeconds` is 3. Players are frozen for the whole break and
the end swap only runs when it expires, so a minute of standing still read
in-game as "the team swap takes way too long". The live server had 60
persisted, so deployment also needs
`css_sm2match_config breaklength 3` (persists).
