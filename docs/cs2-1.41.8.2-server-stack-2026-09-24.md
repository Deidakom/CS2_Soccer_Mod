# CS2 1.41.8.2 server stack (2026-09-24)

## What broke

The CS2 update 1.41.8.2 (2026-09-22) moved functions and virtual tables that
CounterStrikeSharp relies on. CounterStrikeSharp's own fix
([#1433](https://github.com/roflmuffin/CounterStrikeSharp/pull/1433)) changes,
among others:

- Linux signatures: `CEntityInstance_AcceptInput`,
  `CEntityIOOutput_FireOutputInternal`, `CBaseTrigger_StartTouch`,
  `CCSPlayer_ItemServices_CanAcquire`, `CCSPlayer_WeaponServices_CanUse`,
  `CCSGameRules_TerminateRound`, `IGameSystem_InitAllSystems_pFirst`
  (`CheckTransmit` was dropped);
- virtual function offsets (Linux): `CBaseEntity_Teleport` 162 → 164,
  `CBasePlayerPawn_CommitSuicide` 384 → 387, `CCSPlayerController_Respawn`
  272 → 276, `CCSPlayerController_ChangeTeam` 102 → 104,
  `CBaseEntity_IsPlayerPawn` 168 → 170;
- the hl2sdk revision (new `CEntityInstance` and `INetworkGameServer` vtables).

SoccerMod calls `AcceptInput` (ball wake/motion inputs) and `Teleport`
constantly. On CounterStrikeSharp v1.0.374, `AcceptInput` fails and
`Teleport` calls a different virtual function. Patching v1.0.374's gamedata is
not enough: its native side is compiled against the old hl2sdk.

CounterStrikeSharp v1.0.375 (2026-09-24) carries the fixes, and it is the first
release built on KHook
([#1418](https://github.com/roflmuffin/CounterStrikeSharp/pull/1418)). It
needs Metamod:Source 2.0 build 1467 or newer (it is built against 1469), and
KHook Metamod refuses SourceHook plugins (plugin API 17), including the
previous `soccermod_native.so`.

## What changed

- `deploy/testserver/update-server.sh` installs the tested pair Metamod build
  1469 + CounterStrikeSharp v1.0.375 by default. It refuses any mismatched pair
  before changing anything. A Metamod change also installs the native bridge
  built for that hook line. The SourceHook pair stays available for older CS2
  builds (`--metamod-build 1410 --cssharp-version v1.0.374`, ball spin off).
- The native bridge is rebuilt against Metamod `fa6f80e` (KHook, plugin API
  18) and hl2sdk `625bfd4`, the revision CounterStrikeSharp v1.0.375 uses. It
  reads the `CEntityInstance_AcceptInput` signature from CounterStrikeSharp's
  `gamedata.json` at load and falls back to built-in signatures for 1.41.8.2
  and earlier. It uses a signature only when it matches exactly one place in
  `libserver.so`. It calls the function with CounterStrikeSharp's full
  prototype, including output id and parameter map. A future CS2 update that
  only moves `AcceptInput` therefore needs a CounterStrikeSharp update, not a
  rebuild.
- `src/native-plugin/soccermod_native/build-linux.sh` builds the bridge from
  pinned Metamod, hl2sdk and AMBuild revisions (`--install` updates the
  payload).
- Update script fixes: installing a CounterStrikeSharp release whose staged
  `plugins`/`configs` held a file absent on the server aborted silently. The
  generated `rollback.sh` now moves every replaced CounterStrikeSharp runtime
  part aside.

## Verification

- The plugin DLL built against CounterStrikeSharp.API 1.0.373 (what
  `--build-plugin` produces) references 282 API members. All resolve with
  identical signatures in the v1.0.375 release's `CounterStrikeSharp.API.dll`
  (metadata comparison; the same check reports 50 missing members against
  1.0.250). The source also compiles against v1.0.375 without warnings. The
  user message ids SoccerMod hooks (118, 208) are unchanged.
- Native bridge: host-side checks of the scanner and the gamedata reader
  (`test/native`, run by `test/test_native_bridge.py`), mutation-tested. The
  binary's glibc requirement is unchanged (2.38). Besides `libtier0.so` it
  now also links the system's `libm` and `libgcc_s`.
- `update-server.sh` was simulated end to end with a stubbed SteamCMD,
  systemd and an A2S/RCON server. Scenarios: SourceHook stack plus CS2 update
  to the KHook pair, an idempotent re-run, `rollback.sh`, rejected pairs, the
  SourceHook path, a run without `--sync-payload`, and `--check`.
- Needs the live server: after the update, `meta list` shows
  CounterStrikeSharp and SoccerMod Native Physics Bridge. The console shows
  `[SM2NATIVE] resolved CEntityInstance_AcceptInput at 0x… (CounterStrikeSharp
  gamedata signature)`, and `css_plugins list` shows CS2 SoccerMod.

## Server commands

```sh
cd /root/cs2-soccermod-src && git pull
sudo bash deploy/testserver/update-server.sh --check
sudo bash deploy/testserver/update-server.sh --build-plugin --sync-payload
```
